# v0.5 Implementation Log

## Decisions taken

1. Kept engine integration in a new `src/engine-integration.js` module so v0.1–v0.4 simulation/state/semantic authority does not depend on Unity concerns.
2. Added a second Pi extension rather than enlarging `narrative-runtime.ts`; package discovery can keep authoring runtime and engine bridge separately maintainable.
3. Chose at-least-once delivery plus stable IDs/ACK instead of claiming exactly-once semantics.
4. Kept ACK ledgers outside the NarrativeEvent stream because an engine acknowledging delivery does not change story truth.
5. Made checkpoint/save/export files rebuildable or derived artifacts.
6. Introduced explicit integer project schema versioning and preserved old string labels during migration.
7. Added a hand-written Unity DTO sketch for v0.5; code generation is deferred.

## Validation performed

- new engine-integration regression tests
- ACK idempotency and unknown-ID rejection
- incremental export filtering
- deterministic save snapshot identity
- checkpoint tamper detection
- legacy project schema migration
- malformed consequence validation
- localization-key generation
- Unity-friendly array DTO checks
- CLI validator against a schema-v1 fixture
- package structure check

## Review note

The protocol intentionally leaves transport unspecified. A future Unity bridge can use files, Pi RPC, a local process, or another IPC transport without changing delivery IDs or DTO semantics.

## CI

v0.5 adds `.github/workflows/validate.yml`. It intentionally does not require installing Pi peer dependencies because the deterministic JS regression suite and package/project validators do not invoke live LLM sessions. Pull requests run the full Node regression suite plus engine-contract validation against Roadside Station.
